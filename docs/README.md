# OctoAcme Project Management Docs

Welcome — this folder contains the OctoAcme project management process documents. Use this README as the single entry point to discover our lifecycle, core principles, and links to the detailed docs.

## Purpose
Provide a concise summary of how OctoAcme runs projects and link to the detailed process docs used by the delivery team, product, and stakeholders.

## Quick process overview
- Customer-first — prioritize customer value and usability.
- Iterative delivery — deliver small, testable increments and iterate based on data.
- Clear ownership — each project has a named PM and Product Lead.
- Data-informed decisions — measure impact and iterate with evidence.
- Transparency — keep shared, living documentation for decisions and processes.

## Lifecycle (high level)
1. Initiation — confirm the business need, stakeholders, and success criteria. (See: Project Initiation Guide)
2. Planning — scope work, identify dependencies/risks, and create the backlog and release plan.
3. Execution & Tracking — deliver increments, run CI/tests, track progress and metrics, and escalate blockers as needed.
4. Release & Deployment — follow pre-release checks, automated deployment, rollback/mitigation plans, and post-deploy verification.
5. Retrospective & Continuous Improvement — capture learnings, add action items to the backlog, and measure impact.

## How to request updates
To propose a new document or change an existing process doc, open a GitHub issue using the "Add Content to Project Management Process Docs" template located in .github/ISSUE_TEMPLATE/. Provide the target doc (or select "new document"), the content summary, rationale, and suggested text.

## Acceptance criteria (example)
- Content aligns with existing process docs.
- Update improves clarity or closes a documented gap.
- Proposed content has been reviewed with stakeholders if needed.
